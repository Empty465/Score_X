Score X 미니게임 개발 안내
==========================

팀원들이 바이브 코딩으로 미니게임을 추가할 때 아래 절차와 규칙을 따라 주세요.

개발 환경
--------

- VS Code에서 프로젝트를 엽니다.
- Node.js 24 이상을 사용합니다.
- Git 작업은 터미널 명령 대신 VS Code의 소스 제어 화면을 이용합니다.
- 각자 개인 브랜치에서 작업합니다. 브랜치 이름은 Dev_이름 형식입니다.
  - 새 작업: 하단 브랜치 이름을 눌러 Dev를 선택하고 최신 상태로 동기화한 다음, 분기 만들기를 선택해 개인 브랜치를 만듭니다.
  - 기존 작업: 본인의 개인 브랜치로 전환해 이어서 작업합니다.

미니게임 추가
------------

현재 게임 목록과 표시 정보는 games/catalog.js에 등록하며, 게임을 선택하면 해당 모듈이 동적으로 로드됩니다.

새 게임을 만들 때 주로 다루는 파일:

- games/<게임ID>.js — 게임 로직과 이벤트
- games/catalog.js — 고유 ID, 이름, 아이콘, 설명 등 게임 정보
- index.html — 게임 화면 본문 (id="view-<게임ID>")
- styles.css — 게임 화면과 카드 스타일

게임 메뉴와 게임 선택 카드는 카탈로그에서 생성되므로 HTML에 중복으로 추가하지 마세요. 게임 모듈은 window.Playground.registerGame('<게임ID>', lifecycle)로 등록하고, 최고 기록과 점수 제출은 window.Playground의 공통 API를 사용합니다.

자세한 연결 방법은 games/README.md를 확인하세요.

중요: 현재 구조는 모듈 분리와 지연 로딩을 적용했지만 iframe 격리는 아닙니다. Main Shell과 게임은 같은 브라우저 문서와 JavaScript 실행 환경을 공유합니다. 게임 모듈에서 서버 API나 DB를 직접 다루지 말고 공통 API를 이용해 주세요.

개발 순서
--------

1. 게임 규칙, 조작 방식, 종료 조건, 점수 산정 기준을 정합니다.
2. games/README.md, games/catalog.js, 비슷한 기존 게임 모듈을 확인합니다.
3. 필요한 범위에서 게임 모듈·카탈로그·화면·스타일을 수정합니다.
4. VS Code 소스 제어에서 변경 파일과 diff를 확인합니다.
5. 브라우저에서 게임을 실행해 시작, 재시작, 화면 이동, 종료 동작을 확인합니다.
6. 변경을 스테이징하고 커밋한 뒤 개인 브랜치에 게시합니다. 팀에서 정한 절차에 따라 통합을 요청합니다.

실행 및 브라우저 테스트
----------------------

VS Code 터미널에서 다음을 실행합니다.

    node server.js

서버가 실행되면 브라우저에서 다음 주소를 엽니다.

    http://localhost:3000

테스트가 끝난 뒤 서버를 종료하려면 터미널에서 Ctrl+C를 누릅니다.

점수·서버 변경 주의
------------------

게임을 카탈로그에 등록했다고 점수판의 최고 기록 집계까지 자동으로 지원되는 것은 아닙니다. 새 게임의 점수를 저장하고 랭킹에 반영해야 한다면 담당자와 먼저 범위를 조율해 주세요.

서버, DB 스키마, 점수·보상·투자 규칙, 게임 ID, DOM ID, 공통 인터페이스를 바꾸는 작업은 다른 기능에도 영향을 줄 수 있으므로 팀과 먼저 공유합니다. DB/scorex.sqlite 파일은 직접 편집하거나 테스트 데이터로 변경하지 마세요.

바이브 코딩 요청 예시
--------------------

새 미니게임 <게임 이름>을 추가해줘. 먼저 games/README.md, games/catalog.js, 비슷한 기존 게임 모듈을 확인해 현재 구조를 따라줘. 게임 ID는 <id>야. 필요한 범위에서만 게임 모듈, 카탈로그, 화면, 스타일을 수정해. 점수 저장은 window.Playground 공통 API를 사용하고 서버 내부 구현은 게임 모듈에 넣지 마. 기존 게임과 관계없는 정리나 의존성 추가는 하지 말아줘. 점수 집계나 서버 수정이 필요하면 영향 범위를 먼저 알려줘. 마지막에 수정 파일과 브라우저 테스트 방법을 정리해줘.

보안 및 변경 검토
----------------

- API 키, 비밀번호, .env, 실제 계정 정보나 DB 내용을 AI 프롬프트와 스크린샷에 넣지 않습니다.
- 다른 팀원의 변경을 임의로 덮어쓰거나 삭제하지 않습니다.
- 요청하지 않은 대규모 리팩터링, 파일 삭제, 패키지 설치가 생기면 필요성을 확인합니다.
- 구현 후 브라우저에서 점수 반영과 기존 게임 동작에도 문제가 없는지 확인합니다.
