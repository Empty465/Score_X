## 5. 미적용 기능 구현 및 기존 기능 보완

### 5.1. 계정 인증 및 게스트 모드
- [ ] 정규 회원가입 및 로그인 구현 (계정 ID, 비밀번호, 닉네임)
- [ ] 비밀번호 안전 저장 및 세션 기반 인증 상태 유지 구현
- [ ] 기존 이름 기반 사용자 데이터를 계정 체계로 이전하고 점수·크레딧·아이템 보존
- [ ] 익명 게스트 세션 생성 및 게스트 상태 유지
- [ ] 게스트 점수·재화는 결과 화면에서만 표시하고 DB 저장·랭킹·투자·상점에 반영하지 않도록 분리

### 5.2. Career 모드 및 랭킹
- [ ] 무작위 5개 미니게임을 연속 플레이하는 Career 모드 추가
- [ ] Career 진행 상태와 게임별 결과를 저장하고 중단 후 이어하기 처리
- [ ] Career 회차 점수를 별도 기록하고, 티어 산정은 모든 미니게임 최고 기록 합계를 기준으로 처리
- [x] 최고 기록 합산 점수의 티어 랭킹과 현재 보유 CR 잔액 랭킹을 별도로 제공
- [x] 미니게임 플레이 완료 후 점수 100점당 1 CR, 최소 1 CR 지급 규칙 유지 및 검증
- [ ] 일일 1회 출석 보상 지급 및 중복 수령 방지

### 5.3. 미니게임 통신 및 모듈 확장 구조
- [ ] Shell과 게임 모듈 간 표준 postMessage 프로토콜 구현
- [ ] 게임 시작 메시지에 난이도(EASY/NORMAL/HARD)와 seed 전달
- [ ] 게임 종료 메시지에 gameId, finalScore, playTimeSeconds, isCleared 전달
- [ ] 메시지 발신 출처·게임 ID·데이터 형식을 검증하고 허용되지 않은 메시지는 거부
- [ ] 게임 모듈을 독립적으로 등록·추가할 수 있도록 로딩 구조 개선
- [ ] 기존 6개 게임을 새 통신 규약으로 연결하고 점수 저장·투자 진행 회귀 검증

### 5.4. 점수 검증 및 데이터 신뢰성
- [ ] 서버가 발급한 게임 seed와 플레이 세션 식별자 관리
- [ ] 게임별 점수 범위 및 플레이 시간 검증 규칙 구현
- [ ] 지원 가능한 게임의 액션 타임스탬프·체크섬 검증 적용
- [ ] 중복 제출 및 세션 재사용 방지
- [ ] 비정상 점수·시간·액션 기록을 거부하고 서버 로그에 남김
- [ ] 클라이언트 제출만으로 점수를 신뢰하지 않도록 서버 점수 검증 강화

### 5.5. 조종석 UI 및 테마 적용
- [ ] 모든 게임 화면을 공통 우주선 조종석 모니터 프레임 안에 배치
- [ ] 공통 컬러 팔레트 적용: Navy `#0B0E14`, Cyan `#00F0FF`, Red `#FF3366`, Green `#00FF88`
- [ ] Orbitron, Rajdhani, Roboto Mono 등 SF·모노스페이스 계열 폰트 적용
- [ ] PC·모바일 화면에서 프레임과 게임 조작 UI 반응형 검증

### 5.6. 데이터 이전 및 통합 검증
- [ ] 기존 SQLite 사용자·점수·투자·상점 데이터가 보존되는 스키마 이전 구현
- [ ] 데이터 이전 전후 건수와 주요 합계 검증 및 실패 시 복구 절차 마련
- [ ] 인증, 게스트, Career, 최고 기록 합산 점수판, 보유 CR 점수판, 보상 지급, 출석, 투자, 상점 API 테스트 추가
- [ ] 기존 게임별 점수 적립과 투자 임무 진행의 통합 회귀 테스트 수행
- [ ] 개발 및 배포 환경을 `package.json`의 Node.js 24 이상 요구사항에 맞추고 실행 검증
